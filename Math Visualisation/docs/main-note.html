When does each part run?

1 — START

The page loads: check every project, run every setup(), enter() the chosen project, then set up the canvas and the mouse and start the frames.

2 — SWITCH

The menu changes: leave() the old project, show the new project's panel, enter() the new one.

3 — FRAME

About 60 times a second, for the current project only: update(dt), then clear, grid, draw(), grid numbers.

WORKED EXAMPLEopen the page, choose Tiny Steps, press Run, drag
FRAME1 ÷ 60 s ≈ 16.7 ms apart, on a 60 Hz screen
RUNN = 20: a step every 3 ÷ 20 = 0.15 s, so about every 9th frame
TOTAL20 steps in 3 s ≈ 180 frames
page loads menu every frame you click or drag

THE PROJECTS LIST

const projects = { "coordinates": coordinatesProject, "tiny-steps": tinyStepsProject };
  • Each key matches an <option value> in index.html.
  • A new project: import it and add one line here.

PAGE LOADS

  • Every project is checked first. A missing part stops the page with its name: Project "name" is missing: leave.
  • setup() runs once for every project, shown or not.
  • The menu's first choice gets enter(), then the frames start.

EVERY FRAME

  • The browser calls frame() once per screen refresh, through requestAnimationFrame: usually 60 times a second.
  • dt = seconds since the previous frame, about 0.017 at 60 Hz. Capped at 0.1 s, so a hidden tab can't cause one giant jump.
  • Always in this order: update(dt) → clear → grid → draw() → grid numbers.

MENU CHOICE

  • leave() on the old project, then its panel is hidden and the new one's shown.
  • enter() on the new project. Its state is wherever you left it.

BUTTONS

  • A click skips main.js: it runs the handler the project connected in setup().
  • The handler only changes the state. The next frame's update and draw do the rest.

MOUSE

  • input.js, not main.js: on press it asks grab(world).
  • true: every move calls drag(world). false: every move pans the view.
  • Scrolling zooms. Panning and zooming change view, never a project.
main.js decides when.
Clicks go to the project, the mouse goes through input.js.
