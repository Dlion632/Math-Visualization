What do I write in a project file?

1 — STATE

One object with everything the project remembers: numbers, points, whether something is playing.

2 — HELPERS

Small functions with one job each, used by the lifecycle. Nothing outside the file calls them.

3 — LIFECYCLE

Eight parts with fixed names. Each one has a single job. A part may be empty, but it may not be missing.

EVERY LINE remembers changes shows names

STATE

  • Everything that must survive from one moment to the next, in one object called state.
  • Values that never change, like UNIT = 200, go above it as constants.
  • No functions, no drawing.

HELPERS

  • A job you need more than once gets a name: takeStep() is used by both Next step and Run.
  • No math rules: tinyStep() lives in tiny-steps-math.js.

PANEL

  • The id of this project's controls <div> in index.html.
  • The only part that is a value, not a function.

SETUP()

  • Connect each button and input to a small change of state: Run sets running = true.
  • Don't draw here, and don't start timers.

ENTER()

  • Get ready when the project is shown. Often empty.

UPDATE(dt)

  • Whatever changes by itself over time. dt is the seconds since the last update.
  • Collect dt and act when enough has built up: with N = 20, a step every 3 ÷ 20 = 0.15 s.
  • Don't draw here.

DRAW()

  • Show the state with the pens, in world coordinates. Text readouts belong here too.
  • Read the state, never change it.

LEAVE()

  • Pause whatever is in progress: running = false.

GRAB(world) + DRAG(world)

  • grab: return true if this world point hits something draggable.
  • drag: move that thing to the new world point.
  • Nothing to drag: return false and leave drag empty.
